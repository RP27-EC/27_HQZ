# 上板发射机构与热量预算

[返回上板模块索引](README.md) · [返回上板工程说明](../Readme.md) · [裁判链路](../../task_down/docs/referee.md) · [板间协议](board-link.md)

## 职责与许可

- 下板读取遥控/键鼠，D1传递摩擦轮使能、模式、触发与过洞请求；S2沿用消抖，进入下位只关轮一次，后续新G或新鼠标点击可重新开轮，S2不参与底盘选模。D1布局与上板控制代码不变。
- 上板控制两台 RM3508 摩擦轮和 KT4005 拨盘；裁判热量通过 D3、弹速通过新增 D6 同步。D3布局不变；D1 b5 bit6为S2中位、bit7为同帧输入源。
- `launcher_dial.hold_allowed`：板间在线、整车使能、拨盘在线、编码器基准有效、无发射机构故障、无拨盘堵转锁，且过洞暂停解除时保持。
- `feed_allowed`：另需摩擦轮总使能、两轮在线、D1 发射许可有效且过洞请求为零。热量在请求接受时另行检查，不能凭该字段为 1 判断一定会供弹。
- 摩擦轮关闭、S2 中位、热量不足时继续保持；`is_hole=1` 时拨盘停机，退出请求后等待 2000 ms 恢复保持，不依赖升降到位或 `lift.fault_code`。下板发射许可仍独立约束供弹。
- 失能后重新接管当前位置，不追赶旧目标；正常回中位、摩擦轮切换不重采样。

`launcher` 保留原观测入口；`launcher_dial` 为上板本地独立状态，不发送到 CAN。摩擦轮休眠时 `launcher.state` 可为 `SLEEP`，但拨盘仍可能为 `launcher_dial.state=READY`。

保持是有限力矩闭环，允许 100 count 死区，不能保证完全拨不动；死区内速度目标为零，速度环仍提供阻尼。

待发保持的 PID 仍每个控制周期计算。进入保持时立即发送首帧，位置误差不在 100 count 死区内或速度超过 20°/s 时，力矩按 1 ms 间隔发送；误差进入死区且速度不超过 20°/s，连续 100 ms 后才降为 10 ms。单发、连发、制动和摩擦轮/升降 `0x200` 发送周期不变。

## 拨盘阶段

| `launcher_dial.state` | 行为 |
| --- | --- |
| `SLEEP` | 卸力；有效保持许可恢复后接管当前位置 |
| `READY` | 独立待发 PID 保持累计目标 |
| `SINGLE` | 原目标增加 65536 count，释放触发仍完成本发 |
| `REPEAT` | 原连发速度环；释放或许可/热量失效后制动 |
| `STOPPING` | 零速制动；速度不超过 20°/s 或达到 120 ms 后锁定当前位置 |
| `REVERSE/RELOAD` | 连发堵转的反退/前向恢复，最多3轮 |
| `FAULT` | 故障卸力，禁止保持与供弹 |

- KT 首个有效运动反馈建立累计编码器基准；65536 count 为电机编码器一圈，机构位移仍取决于传动。
- 单发完成需误差不超过 500 count、速度不超过 20°/s，连续 20 ms；保持原目标，清除供弹积分。
- 500 ms 未完成：增加 `timeout_count`，记录原因 6，停止追旧目标，制动后保持停止位置，不自动补射。
- 总发射许可撤销、热量基准失效或热量超过上限会中止供弹；单发预占引起的普通热停发锁不打断本发。
- 启动发送失败只保留一个已通过许可检查且预占热量的请求，最长 50 ms；启动成功才增加目标，超时或许可撤销取消。
- 遥控分支忙碌、热量不足时拒绝新升沿；键鼠分支最多保留一个2 s达速请求；拒绝、超时、中断以及连发热停发后均需释放触发再供弹。
- 未执行或中止单发的热量预占不退回，等待裁判校准或冷却。
- `SPINUP/INIT` 保留枚举兼容值，主路径不进入；无效的固定归零与待发停机配置已删除。

## 热量预算

- D3 保留上限、枪管热量、冷却率、源序号及有效位；新源序号校准本地估计。
- 初始预算未建立时禁发；D3 失联后沿用已有参数估算，不将失联解释为零热量。
- 每发预占 10 热量单位，安全余量 20，恢复余量 30，最高射频 15 发/s。
- 降速起点 200、平衡区起点 50；D3 新鲜度为 100 ms；训练开关及训练上限/冷却率均为 0。
- 查看 `launcher_heat.source/ready/blocked/remaining/target_rate` 区分预算拒绝与机械无响应。

## 单发弹速闭环

单发与连发均参与弹速修正；单发按逐发关联采样，连发按达速后的新事件采样。

- 基准 6000 rpm、目标 22.0 m/s，依据人工提供的实测关系；启动及目标调整使用 20 rpm/ms 斜坡。双轮旋向正确、达到最终目标各自 ±100 rpm 并持续 100 ms 后允许新单发。
- 单发在同一目标下三发有效弹速取均值；误差超过 ±0.3 m/s 时，按 `20*(22-均值)` rpm 修正，每组限幅 ±50 rpm，正常目标限制 5400～6000 rpm。到限时置 `at_limit`。左右摩擦轮 PI 在单发、连发及正常升速/制动期间统一改为 Kp=3、Ki=1.5、Kd=0；积分累积限幅仍为500，积分项最大贡献由500增至750 raw，最终电流指令仍限制±5000 raw。
- 首发依赖 D6 心跳确认裁判在线，不要求已有弹速样本。初始零弹速心跳不参与学习。D6 超过 300 ms 未到达或源离线禁止新发射。
- 受理前记录源序号，拨盘实际启动后开始等待；一次仅等待一发，1000 ms 内只接受相邻序号、类型/机构匹配、采样时刻不早于启动的弹速。重复、过期、跳号和关联不明的样本不学习。
- 等待弹速不阻止下一发；拨盘就绪、双轮达速、热量及其它许可满足且释放后重按即可受理，不排队。已启动单发仍按原机械完成/超时规则运行。
- 有效新弹速达到 24 m/s 时锁止新发射，目标降低 10%；达到 25 m/s 另增加越限计数。人工关闭再开启摩擦轮解除锁止并恢复基准，不因模式切换或普通断链解除高弹速锁止。
- 单发反馈超时、关联异常或前一发未反馈就受理下一发时，清空本组样本并增加对应计数，只暂停学习，不锁止供弹、不撤销已受理单发。
- 某发漏发或弹速永久丢失时，不必重新开关摩擦轮即可再发。关联不明时暂停学习；停止发射且无待关联/待启动单发达到隔离时长1000 ms后自动恢复学习。隔离中继续发射会延长学习隔离，但不阻止供弹。
- 模式切换清空关联及样本，并将单发/连发目标恢复6000 rpm。普通切换、重新使能和链路恢复隔离旧反馈1000 ms，并要求释放再触发；已有有效触发许可或本次按住已启动单发时，单发转连发保留按住许可，不额外等待1000 ms，但仍须重新达速。拒绝、制动、离线与高弹速锁止后不继承此许可。

- 连发使用独立 `repeat_target_rpm`，目标22 m/s、死区±0.3 m/s、三条有效反馈均值；按 `100*(22-均值)` rpm 修正，每组限幅±200 rpm，下限5400 rpm，取消连发6000 rpm上限。三发均值19 m/s且允许上调时，目标可从6000修正到6200 rpm。连发启动时以已确认达速建立采样起点；目标调整后重新确认达速再建立起点。起点之后产生的匹配、新鲜、相邻序号事件参与学习；重复、跳号和旧目标反馈不学习。
- 连发向上修正要求双轮反馈有效、沿目标旋向的速度不足各不超过150 rpm，且任一轮没有连续50 ms正向输出饱和；否则本组仍记录均值、清空样本，但保持目标并置 `launcher_speed.raise_blocked=1`。负向修正不受该门槛限制；`at_limit`仅指单发上下限或连发下限。未达速时先恢复现有目标，不追高目标。
- 实际连发负载前馈为 `方向*1000*clamp(目标射频/15,0,1)*fade` raw；`fade=clamp(1+速度不足/100,0,1)`。达到目标仍保留前馈，超速0～100 rpm时线性撤销。1000 raw是人工待标定初值，不是已测负载。
- 普通连发恢复为 `方向*clamp(3*(沿目标旋向速度不足-50),0,3000)` raw；单轮不足达到600 rpm进入强恢复，直接请求该轮正确旋向5000 raw，不足恢复到150 rpm以内退出。强恢复覆盖普通叠加结果，最终指令仍限制±5000 raw。轮速控制约1 ms计算，不等待裁判弹速回传。
- 补偿只作用于请求和许可有效、实际处于连发、热量允许、未锁止且电机反馈有效的摩擦轮。正常摩擦轮控制放在本周期拨盘状态更新之后，进入连发当拍投入；退出连发、反退、松开或保护触发当拍撤销。既有故障卸力与关轮零速制动路径保留。总输出达到限幅且误差仍推动同方向饱和时，撤销本拍积分累加；反向误差允许消除积分，不改公共PID。
- JSCOPE观察 `launcher.fric_l_speed_rpm/fric_r_speed_rpm`、`fric_l_output_raw/fric_r_output_raw`，以及 `launcher_fric_control[0/1]`（左/右）的 `feedforward_raw/recovery_raw/strong_active/forward_saturated_ms`。前馈、恢复量都带实际电机旋向；强恢复时 `recovery_raw`表示覆盖至5000 raw所需的附加量，可能反向抵消已过大的PI输出。饱和时长按正向最终指令计时，非饱和、停机或离线时清零。若掉速期间最终输出持续达到±5000，补偿已无指令余量，需要人工检查供电、驱动与机械负载。
- 连发1000 ms无有效新弹速时，仅增加超时计数、清空样本并重新建立学习达速基准，保持当前目标及按住连发；D6链路/裁判源离线、热量限制、拨盘互锁及24 m/s锁止仍停止供弹。调整过程中不因瞬时掉速强行中断正在连发，达速要求用于启动和每次目标调整后的采样起点。

观察 `launcher_speed.target_rpm/single_target_rpm/repeat_target_rpm/latest_mps/average_mps/sample_count/waiting/at_limit/raise_blocked/guard_latched/block_reason`。`raise_blocked`表示最近完整样本组的连发上调门槛未满足，模式/目标组复位时清零，不用于供弹门控。`waiting` 仅表示等待学习反馈，不表示禁发；超时/关联计数记录单发学习丢弃原因。`target_rpm` 是最终目标，`launcher.fric_target_rpm` 是斜坡中的即时目标。

| `launcher_speed.block_reason` | 含义 |
| --- | --- |
| 0 | 弹速路径允许新发射，仍需其它许可 |
| 1 / 2 | D6或整车链路失效 / 裁判源离线 |
| 3 / 4 | 保留反馈超时/关联故障编号；当前异常仅计数，不用于供弹门控 |
| 5 / 6 / 7 | 高弹速锁止 / 保留兼容编号、不用于门控 / 切换恢复隔离 |

人工先验证固定基准单发，再检查三发修正方向、未达速拒绝、反馈缺失/恢复、24 m/s 锁止与模式切换。另人工记录连发最低弹速、双轮掉速/恢复时间、补偿后的最大弹速及最终输出是否持续饱和；确认长按进入/松开退出连发、三条反馈修正方向、目标调整期间不混用旧样本、漏反馈不停连发及高弹速停连发。初始验收为充分恢复后单发 21.5～22.5 m/s，同时观察首发、最大弹速、双轮反馈、持续饱和和发热。代码限幅及事后保护不能保证每发绝不超过 25 m/s；双板须同步编译烧录，当前只完成静态审查。

本次优化仅修改上板控制，不改变板间报文；上下板仍须使用既有匹配协议。PI同时影响单发和制动，人工重新观察单发过冲和关轮减速。15发/s连发按22 m/s目标、20.9～23.1 m/s区间、至少95%样本在区间内做初步验收，每工况至少100发，报告最低/最高弹速并单独检查约19 m/s低点；同步记录目标/反馈rpm、最终电流指令、实际射频、电压和电机温度。补偿初值和强恢复退出过冲尚未实机验证。

## 无响应观测

| `launcher_dial` 字段 | 含义 |
| --- | --- |
| `state / hold_allowed / feed_allowed / trigger_ready` | 独立阶段、许可、是否已释放触发 |
| `target_angle / target_error / speed_target_dps` | 目标 count、残差 count、速度目标 deg/s |
| `output_current_raw` | 最近力矩指令原始量；失能时显示零指令 |
| `run_tx_status / torque_tx_status / stop_tx_status` | 最近发送结果：HAL 0 成功、1 错误、2 忙、3 超时 |
| `accepted_count / rejected_count / completed_count` | 接纳/拒绝/到位单发数；接纳包含等待启动 |
| `timeout_count / start_timeout_count` | 单发未完成 / 启动超时次数 |
| `pending_single / pending_tick` | 等待启动标志及起点 ms |

`reject_reason`：0 无拒绝，1 热量，2 忙碌，3 通信/电机离线，4 失能/互锁/未释放触发，5 启动超时，6 单发未完成。原因保留到下次接纳；原因 6 计入 `timeout_count`，不增加拒绝请求计数。

HAL 成功仅表示 CAN 驱动接纳发送，不能证明电机执行。目标未变化且拒绝数增长先查许可；目标变化但反馈位移很小，再由人工检查发送结果、电流与机械阻力。

## 人工验收

1. 确认 S2 中位、摩擦轮关闭时保持；过洞请求期间停机，退出请求 2000 ms 后恢复保持，即使升降故障码为 5；失能或断联时卸力。
2. 确认单发累计目标、释放后完成本发，观察到位振荡是否减轻。
3. 确认启动等待 50 ms、单发超时 500 ms 后不补射、不追旧目标。
4. 确认许可或冷却恢复不自动补射，释放并重新触发后才供弹。
5. 无响应时记录拨盘观测、热量状态及电机位置/速度/电流反馈。

### 一个单发请求如何完成

`shoot_level:0→1` 且单发模式 → 检查保持/供弹许可、READY、触发已释放、双轮达速及弹速路径许可 → 预占 10 热量并记录源序号 → 保存一个待启动请求 → KT 启动入队成功 → 旧目标累加 65536 count 并等待逐发弹速 → 位置环给速度目标、速度环给电流 → 误差≤500 count 且速度≤20 deg/s 持续20 ms → 完成计数增加并保持原目标；下一发不依赖上一发弹速反馈，仅保留拨盘就绪、达速、热量、链路及高弹速保护等门控。

忙碌时的新上升沿被拒绝，当前没有多单发队列；连续快速点击不保证每个点击都被执行。启动待发和动作超时是不同阶段，分别为 50 ms、500 ms；超时后的重新供弹要求释放触发。

### 达速、热量新鲜度与触发是三个条件

- `fric_ready` 是新单发受理及连发启动门槛，不并入 `feed_allowed`，避免发射掉速强行中止已接受单发；摩擦轮开启不等于已经达速。
- 热量预算尚未建立时 `ready=0`。建立后 D3 超时会转 `LAUNCHER_HEAT_ESTIMATE`，沿用已有上限/冷却率继续估计，当前不是“D3 超过100 ms 一律停发”。
- 单发预占热量；连发按编码器正向进展高水位累计增热，反向回退不会立即抵消已累计增热。同一 D3 源序号不会每10 ms重复覆盖本地估计。
- 下板长按判断来自按键更新计数，上板还检查拨盘状态和 `trigger_ready`；连发模式位为1仅表示请求，不能当作拨盘正在连续运动的证明。

可用于讲解：“发射请求与执行分在两板；单发靠累计位置目标，连发靠独立速度环，热量模型限制是否接受请求和目标射频，拨盘停发后制动并保持。”

## 一键射击、堵转与重连

- 键鼠左键新按下自动开轮，最多保存一个 `wait_single`，最长2000 ms；达速且原有热量/弹速许可有效后执行。短按松开仍保留本次单发；长按转连发不会额外排入单发。G关轮、断联、过洞、保护或超时取消请求。
- `pending_single`仍是已完成许可与预算预占后的50 ms执行窗口，与达速等待独立。
- 堵转检测 `LAUNCHER_PROTECT_ENABLE=1`，连发退让 `LAUNCHER_DIAL_JAM_ENABLE=1`。拨盘100 ms启动宽限，低速≤10°/s且电流≥1500 raw持续200 ms，或有效输出≥1500 raw、低速且300 ms位移<100 count确认堵转；单发第一次反退1/4格后等待新触发，第二次确认堵转卸力；连发前两次反退一格后继续正转，第三次确认堵转卸力。
- 待发保持≥600 raw持续1000 ms停机；左右摩擦轮分别在启动1000 ms后检测≤100 rpm且电流≥3000 raw持续200 ms，任一轮触发即停两轮和供弹。
- 单发第一次堵转从实际位置反退16384 count，到位或200 ms后制动并保持当前位置；不自动补射，成功完成一发才清零失败次数。500 ms单发动作超时仍只制动保持，不计堵转。独立拨盘锁、保持过载和摩擦轮故障恢复均保留1000 ms冷却及电流/驱动检查；新鼠标请求可保留等待恢复，但仍受2000 ms请求上限约束。拨盘1500 raw与单发、连发PID输出上限相同，反馈电流未达门槛且无进展条件未满足时不会计堵转；摩擦轮3000 raw门槛不变，实际触发及温升由人工核对。
- 独立以50 ms读取KT状态；新鲜运动反馈→零电流→RUN→新反馈确认→当前位置接管。HAL成功仅为发送入队；反馈失效会取消旧请求；新点击可跨RUN恢复等待，位置目标在新反馈后重新对齐。
- `launcher_protection`观察原因、次数、停机时间和恢复阶段（0读状态、1等待启动反馈、2就绪）。原因1拨盘堵转、2保持过载、3摩擦轮堵转、4其他锁存故障。
- `reject_reason`新增9堵转保护、10达速等待超时；`wait_single/wait_tick`观察达速等待。上电、断联恢复后先释放左键，再接受新按下。
- 仅做源码静态核对；未编译、未烧录、未执行硬件验收。


## 断联恢复与过洞供弹互锁

- D1 b5 bit0仅请求摩擦轮，bit5独立许可供弹。下板板间/遥控离线立即清请求；重连后须重新操作S2或G，按住触发不补射。
- 摩擦轮请求与供弹均不依赖升降顶部、PAUSED或故障记录。下板无过洞请求时允许供弹；上板保留过洞停机及退出后2000 ms延时，仍检查链路、拨盘和发射保护。
- 互锁期间继续采样S2和按键历史；解除后须释放再触发。供弹阻断期间不累积trigger_ready，取消待发请求；拨盘原有过洞停机和退出延时保留。
- `launch.block_reason`（下板）：0无上述拦截、1未解锁、2过洞互锁、3遥控/板间失效；4/5保留未使用。
- `launcher.feed_block_reason`（上板）：0无上述拦截、1未请求开轮、2过洞互锁或退出延时、3整车/板间失效、4全局保护锁存、5拨盘堵转锁。值0不代表达速、热量、拨盘恢复等全部条件满足；继续看fric_ready、launcher_dial和launcher_speed。
- 原全局保护仍按1秒冷却、释放再触发、电流回落和驱动错误解除恢复；拨盘堵转锁按S2回中/左键释放后重新按下请求恢复，仍等待1秒冷却。全局恢复要求双摩擦轮反馈在线且新鲜。不因重连清除故障。
- 两板必须配套更新。旧下板bit5恒0会使新上板禁止供弹；旧上板不消费bit5，不能作为兼容运行组合。
- 本次只做源码回读和静态审查，未编译、未烧录、未实机验证。


## 拨盘堵转退让与独立卸力

- 堵转入口统一使用现有保护检测；单发和连发分别计数，只有新的确认堵转才加一次。单发首次退让、第二次失能，连发前两次退让、第三次失能；松手或普通模式切换不清零失败记录。
- 连发每次从实际堵转位置反向65536 count（电机约360°），到位或200 ms后直接恢复正常速度供弹；不再返回反退起点，不因恢复定位或正转确认超时重复反退。再次确认堵转才进入下一次反退或卸力。
- 连发正转确认要求新鲜反馈、供弹方向速度>10°/s连续300 ms且正向进展>100 count；成功后连发堵转数清零。松手后再次连发仍对保留的堵转计数执行成功确认；没有确认成功时保持次数，不设置自动重退定时器。
- 单发首次堵转从实际位置反向16384 count（1/4格），到位或200 ms后制动并保持当前位置，等待新触发。单发反退结束不增加完成发数、不清零失败次数；反退期间不接纳额外点击。单发正常到位后清零单发失败数，500 ms普通动作超时不计失败、不反退。
- 单发第二次或连发第三次确认堵转，先下发零力矩、撤销旧目标，再置 `launcher_dial.jam_locked=1`，清空PID、待发及旧恢复请求，立即发送 `MOTOR_CLOSE_ID`（0x80）失能，之后每50 ms重发，发送失败仍重试。锁定期间不发送力矩闭环、RUN或位置保持；HAL结果只代表入队结果，实际卸力必须人工验收。不置整套 `launcher.fault`，摩擦轮按原请求继续转；真实摩擦轮故障仍可独立停整套发射机构。
- 遥控S2消抖后处于中位，或鼠标释放后重新按下，冷却1000 ms且电流/驱动检查通过后清独立堵转锁和尝试数。清锁后目标重新取当前位置；S2中位恢复当前位置闭环保持，不补射，鼠标新点击同时保存本次发射意图。驱动启用仍需发送成功及新反馈确认。
- D1 b5 bit6是遥控S2中位，bit7是同次下板输入处理的来源（0遥控/1键鼠）。D5 b0 bit3单独携带发射来源，与D1来源核对；D5 b6点击序号去重。失联/重连本身不会清锁，也不补执行旧点击。两板须配套更新。
- 松手或许可失效会取消恢复并制动/停机；反退不抵扣热量，恢复到已走过的位置不重复计热，继续向前超过原位移高水位后才增加热量。

| 观测量 | 值与含义 |
| --- | --- |
| `launcher_dial.jam_attempts` | 0~3，连发确认堵转次数，第三次失能 |
| `launcher_dial.jam_locked` | 1为仅拨盘卸力锁定 |
| `launcher_dial.jam_phase` | 0正常、1反退、2保留兼容值、3正转确认、4锁定 |
| `launcher.feed_block_reason` | 5为拨盘堵转锁，4仍为全局保护 |
| `launcher_jam_count` | 累计单发与连发确认堵转次数，uint8循环 |

人工验收：确认连发前两次各退一格后持续正转、无新堵转不自行反退、第三次失能；单发第一次退1/4格后等待新触发、第二次失能；正常供弹清零对应计数、普通超时不计堵转。检查锁定后持续按住不能自启、S2回中/左键重新按下恢复、各阶段断联/过洞/热停取消及连发松手取消。核对输入切源时D1/D5先后到达不误清锁，观察退距、方向、反馈电流、失能后实际受力及热量高水位，不以HAL入队成功代替动作证据。

### 单击、松键与恢复请求

- 下板在短临界区一起发布点击序号和发射许可；上板以输入快照消费序号，一次最多保存一个请求，不排队。
- 短按松开保留一发；长按松开取消尚未执行的请求，并制动正在进行的供弹/退让。摩擦轮保持运行；G关闭、互锁、断联和超时取消待发。
- 连发同时要求新鲜D1、D5（各不超过50 ms）、一致发射来源、D1触发及D5左键电平；遥控发射不要求鼠标电平。
- `launcher_click.single_failures`为连续单发堵转次数0~2；`pending`为一发待执行请求；`mid_pending`独立锁存S2恢复请求，避免冷却期间丢失中位动作；`recover`为新鼠标恢复请求。

## 关控制动与S2恢复

- 关控或关轮立即置零速目标，用原摩擦轮速度环主动制动，电流限幅仍为±5000 raw；双轮反馈有效且速度均≤100 rpm持续20 ms后清PID、输出零电流。离线轮直接零电流；真实发射机构故障沿用原保护停输出，物理停转需要减速时间。
- 单发正常完成一发才清零失败次数；首次反退结束和未锁定时S2普通回中不清零。普通500 ms动作超时不直接计堵转，1500 raw电流门槛及速度、位移判据保持原值。
- S2中位由新鲜D1报文独立确认，不依赖D5有效位、鼠标输入源或中位边沿；锁定时检测到中位即锁存恢复请求，D5失效不再清除该请求。关控或D1超过50 ms未更新时清除S2恢复请求；重新收到有效中位后可再次申请。独立拨盘锁及拨盘堵转/保持过载导致的全局保护均可处理。保留1000 ms冷却、拨盘电流低于1500 raw、反馈有效及驱动错误检查；真实摩擦轮故障不能仅由S2回中清除。
- 冷却期间回中请求不丢失，满足条件后清锁和计数，重新采集当前位置，零力矩→RUN→新反馈确认，恢复原力矩闭环位置保持；静止时允许电流为0。S2中位恢复不补射，再上拨按原方式发射；原鼠标恢复入口保留。
- 人工验收关控立即开始制动、停稳后零电流；单发首次退1/4格、第二次失能及S2恢复；连发第三次失能及S2恢复；重复操作和冷却期间请求保留。当前仅完成源码静态核对，未编译、测试或烧录。
